# 3C509B-TPO для Sprinter в MAME

Эта сборка добавляет ISA8-карту `3c509b` для машины `sprinter` — модель
3Com EtherLink III 3C509B-TPO (register-level, написана с нуля, готового
ядра 3C509 в MAME нет). В отличие от `rtl8019as`, карта не эмулирует
NE2000-совместимый интерфейс: программная модель — родная 3Com EtherLink III
(окна регистров 0-6, legacy ID-порт активации), как на реальном 8-битном
3C509B. Подробная инженерная спецификация и список известных упрощений —
в `MAME_3C509B_ISA8.md`.

## Запуск

```bash
../mame/mame sprinter -isa1 3c509b
```

Карту можно ставить в `-isa0` или `-isa1`. Типичная конфигурация оставляет
`-isa0 zxbus_adapter` и ставит Ethernet-карту в `-isa1`.

Сетевой backend выбирается стандартными средствами MAME:

```bash
../mame/mame sprinter -isa1 3c509b -networkprovider pcap
../mame/mame -listnetwork
```

Конкретный host-интерфейс — через меню MAME `Configure Network Devices`
(сохраняется в `cfg/sprinter.cfg`), либо `-nw0 <interface>`.

## Активация: настоящая legacy ID-последовательность

Карта не активируется автоматически. Как и реальный 3C509B, она отвечает
только на ID-порту (`0x100`-`0x1F0`, шаг `0x10`, дефолт `0x110`), пока не
получит корректную ID-последовательность:

1. Два подряд байта `0x00` в ID-порт — сброс/армирование сиквенсера.
2. 255 байт LFSR-последовательности, начинающейся с `0xFF`
   (полином `0xCF`: `next = (v&0x80) ? ((v<<1)^0xCF) : (v<<1)`).
3. Карта переходит в командный режим ID-порта. Основные команды:
   - `0x80..0xBF` — прочитать слово EEPROM (биты 5:0 = адрес) в регистр
     EEPROM Data (он же contention-сдвигатель); результат читается 16
     обратными чтениями ID-порта (MSB first, бит = `0xFE | bit15`).
     Занимает 162 мкс (документированное Read Register); чтения ID-порта
     внутри этого окна **не** сдвигают регистр — ни новое слово не
     появляется раньше времени, ни старое состояние сдвига не уезжает.
   - `0xC0..0xCF` — Global Reset.
	- `0xD0..0xD7` / `0xD8..0xDF` — Set Tag / Test Tag (для нескольких карт
	  на шине; на Sprinter обычно одна карта).
   - `0xE0..0xFE` — записать биты 4:0 в Address Configuration и
     активировать карту по этому адресу.
	- `0xFF` — активировать карту по адресу из EEPROM (обычно `0x300`).

`Set Tag 0` не исключает карту из contention. Поэтому уже активированная
карта с tag 0 снова участвует в следующей полной ID-последовательности:
две программы обнаружения можно запускать подряд без power cycle и без
обязательного Global Reset.

После активации операционное окно (16 портов) появляется по выбранному
I/O base и работает как обычный 3C509B: `Command/Status` на `+0x0E/+0x0F`
во всех окнах, `Select Window` для доступа к окнам 0-6.

DIP `Activation` позволяет включить `Auto-activate at reset` для быстрой
отладки без реальной ID-последовательности — но это упрощение, а не
поведение реальной карты; для тестирования драйвера использовать
`Real (ID sequence required)` (default).

## 8-битный доступ (B-revision)

3C509B — первая ревизия EtherLink III с официальной поддержкой 8-битных
слотов. Каждый 16-битный регистр — это два последовательных 8-битных
цикла: младший байт, затем старший; сама 16-битная операция (включая
запись команды) выполняется в момент записи **старшего** байта. Чтение
симметрично: чтение чётного офсета возвращает младший байт и защёлкивает
старший, следующее чтение нечётного офсета отдаёт защёлкнутый старший
байт.

Исключения (байтовый поток, латч не участвует):

- `Window 1 +0x00` и `+0x02` — RX/TX FIFO (только эти два офсета; `+0x01`
  и `+0x03` не отвечают: чтение `0xFF`, запись игнорируется);
- `Window 1 +0x0A` (Timer) — свободно бегущий 8-битный счётчик с шагом
  3.2 мкс (10 МГц/32), останавливается на `0xFF`; сбрасывается на каждом
  фронте «неактивно→активно» внутреннего запроса прерывания и командой
  `Request Interrupt` (документированный способ запустить счётчик);
- `Window 1 +0x0B` (TX Status) — чтение **не** удаляет запись из стека,
  запись (любым байтом) удаляет одну голову стека;
- `Window 3 +0x05` (ROM Control) — отдельный байт, нет boot ROM;
- `Window 6 +0x00..+0x08` — счётчики статистики, read-and-clear по байту.

## Параметры карты (DIP)

Все параметры реализованы как MAME input ports (меню Configure Options).

I/O base: 31 значение, `0x200..0x3E0` шагом `0x10`, default `0x300`.

IRQ: `IRQ3` (default), `IRQ5`, `IRQ7`, `IRQ2/9`. **IRQ на Sprinter ни к
чему не подключён** (на 8-битной ISA-шине Sprinter вообще нет проводки
IRQ к Z80) — драйвер должен работать только polling'ом через Status.
Значение IRQ хранится в EEPROM/Resource Configuration и видно программно,
но не влияет на активацию или работу карты.

Activation: `Real (ID sequence required)` (default) / `Auto-activate at
reset` (отладка).

EEPROM profile:

- `Dynamic` (default) — MAC генерируется один раз при старте в локально
  администрируемом диапазоне `02:60:8C:xx:xx:xx`; сохранённый в MAME
  `Configure Network Devices` MAC успевает переопределить его до reset.
  PnP resource data взят с физической TPO, а serial/checksum согласуются с
  выбранным MAC;
- `Physical TPO fixture` — неизменяемый 64-word образ карты
  `00:20:AF:5D:69:8B` для регрессий.

Link recovery:

- `Realistic (3 seconds)` (default) — детерминированное восстановление
  10BASE-T после Global Reset;
- `Immediate` — прежнее поведение для быстрой отладки.

На границе pcap короткий корректный Ethernet frame может прийти без
минимального wire padding. В частности, macOS `feth` отдаёт ARP reply длиной
42 байта, хотя физический MAC дополнил бы его до 60 байт перед FCS. Для
внешнего backend модель дополняет такие frames нулями до 60 байт; internal
loopback сохраняет точную длину и поэтому по-прежнему позволяет проверять
runt/error path.

Выбранный MAC виден в логе:

```text
3c509b: power-on reset mac=02:60:8c:xx:xx:xx auto_activate=no
```

### EEPROM и Window 2: разный порядок байтов

В serial EEPROM первый байт пары является старшим байтом слова:
MAC `02:60:8C:12:34:56` хранится как `0260 8C12 3456`. OEM copy
`0Ah..0Ch` использует тот же порядок. Window 2 не меняется: ISA читает
младший портовый байт первым, поэтому слова регистровой пары выглядят как
`6002 128C 5634`, хотя последовательность Station Address остаётся
`02:60:8C:12:34:56`.

Primary checksum `0Fh` вычисляется после формирования words `00h..0Eh`.
Secondary checksum `17h` имеет vital lane по `10h..12h + 18h..3Fh` и
configurable lane по `13h..16h`; `17h` в сумму не входит. В dynamic
профиле PnP serial хранится как `1Ah=word 02h`, `1Bh=word 01h`, а младший
байт `1Ch` пересчитывается LFSR из ISA PnP 1.0a.

Физический golden vector (дважды прочитан `EL3EEP` 8 сентября 2026):

```text
00: 0020 AF5D 698B 9550 B434 0041 4A41 6D50
08: 0010 3000 0020 AF5D 698B 1310 0000 3223
10: 2083 0000 0000 0004 0001 0000 0000 0205
18: 6D50 9550 698B AF5D 0A5B 1010 1982 3300
20: 6F43 206D 4333 3035 4239 4520 6874 7265
28: 694C 6B6E 4920 4949 5015 506D 0295 411C
30: 80D0 22F7 9EA8 0147 0210 03E0 1010 3779
38: 0000 0000 0000 0000 0000 0000 0000 0000
```

## Command-in-Progress (CIP)

Команды (запись `+0x0E/+0x0F`) не выполняются мгновенно: после записи
статус-бит 12 (`CIP`, `0x1000`) выставляется, новые команды до его снятия
игнорируются. Для большинства команд задержка короткая (единицы мкс,
детерминированная, не 0); `RxReset`/`TxReset` — 10 мкс (состояние
применяется в конце окна CIP, а не в момент записи команды); Global Reset —
310 мкс (документированное время перечитывания EEPROM автоматикой
AUTOINIT; всё это время карта не отвечает ни в операционном окне, ни на
ID-порту). Операции EEPROM (окно 0, `+0x0A/+0x0C`) — по таблице
техреференса: чтение 162 мкс, запись/стирание 11 мс, EWEN/EWDS 60 мкс;
после записи/стирания аппаратура сама снимает Erase/Write Enable.
Драйвер обязан опрашивать CIP перед следующей командой — это
соответствует реальному 3C509B и проверено тестами (см. ниже).

## AUTOINIT и восстановление 10BASE-T

Global Reset немедленно переводит внешний тракт в `DOWN`, но цифровой
AUTOINIT по-прежнему завершается ровно через 310 мкс. После активации,
выбора TPO и включения link beat начинается отдельный переход
`DOWN → RECOVERING → READY`; default timer равен 3000 мс emulated time.
Порядок этих трёх действий не важен; уход с TPO инвалидирует его link state,
а повторный выбор TPO запускает новый recovery при уже выполненных остальных
условиях.
Повторная ID sequence, `Set Tag 0`, EEPROM read, activation, `RxReset` и
`TxReset` этот timer не перезапускают.

Media Status bit 11 виден только в `READY`, при включённом link beat и
реально выбранном network backend. Внешний RX до `READY` отбрасывается.
Ранний TX не уходит в backend: он локально занимает обычное время кадра на
10 Мбит/с, завершает FIFO/Notify и теряется без отложенного replay.
Recovery state и оставшееся время timer сохраняются в save state.

## Карта окон и регистров (сводно)

Полная таблица — в `MAME_3C509B_ISA8.md` §6.5. Кратко:

```text
все окна   +0E/+0F   Command / Status (+ CIP, + номер окна в битах 15:13)

Window 0 (Setup)
  +00  Manufacturer ID   = 0x6D50
  +02  Product ID        = 0x9550 (3C509B-TPO)
  +04  Configuration Control  (бит0 ENA, бит2 RST — не хранится;
       биты 13:8 = POR-возможности, для TPO = 0x0F00: внутренний
       10BASE-T трансивер, внутренний VCO, normal operation mode)
  +06  Address Configuration  (биты 4:0 = индекс I/O base)
  +08  Resource Configuration (биты 15:12 = IRQ, справочно)
  +0A  EEPROM Command  (бит15 EBY = busy)
  +0C  EEPROM Data

Window 1 (Operating)
  +00,+02  RX/TX FIFO (байтовый поток)
  +08  RX Status   (0x8000 = пусто; иначе err|remaining, бит14/13/11 = err)
  +0A  Timer (3.2 мкс/тик, насыщение на 0xFF)
  +0B  TX Status (peek/pop, стек глубиной 31)
  +0C  TX Free (округлено вниз до DWORD)

Window 2 — Station Address, +00/+02/+04 (Address0..Address5)
Window 3 — Internal Config (+00 low/+02 high), ROM Control (+05, байт),
           RX Free (+0A), TX Free (+0C, точное значение)
Window 4 — FIFO Diagnostic (+04), Net Diagnostic (+06, loopback биты
           15:12 — writable; 11 TX enabled, 10 RX enabled, 9 TX
           transmitting, 8 TX Reset required, 7 Statistics enabled —
           read-only; ASIC rev биты 5:1 = 2), Ethernet Status (+08),
           Media Status (+0A: бит15 TP enabled, бит13 always 1,
           бит11 Valid link beat detected, writable биты 7/6/3/2)
Window 5 — readback порогов/масок/фильтра (TX Start +00, TX Avail +02,
           RX Early +06, RX Filter +08, Int Mask +0A, Read Zero Mask +0C)
Window 6 — статистика (байтовые счётчики +00..+08, RX bytes +0A,
           TX bytes +0C), только при Statistics Enable
```

FIFO Diagnostic (`Window 4 +04`) — по раскладке техреференса §6.31:
бит15 RX receiving, бит13 RX Underrun (чтение пустого FIFO или за
пределами padding-байтов), бит11 RX Overrun (RX-партиция заполнена),
бит10 TX Overrun (запись сверх TX Free). Биты 15 и 11 отражают текущее
состояние, биты 13 и 10 — sticky и одновременно взводят Adapter Failure
(бит 1 статуса); снимаются только `RxReset`/`TxReset`/Global Reset, как
и требует техреференс («The host must issue the appropriate Reset
command to clear this condition»). BIST-биты 7:0 на ревизии B
зарезервированы.

Read Zero Mask (`SetStatusEnb`, команда 15): **установленный** бит
делает соответствующий источник статуса видимым, сброшенный — читается
нулём и не может вызвать прерывание. На power-up маска равна нулю, то
есть все маскируемые индикации читаются нулями, пока драйвер их не
разрешит; Interrupt Latch (бит 0) маске не подчиняется, Command-in-
Progress лежит вне 11-битного аргумента и виден всегда.

Статистика: бит 7 статуса (Update Statistics) взводится, когда счётчик
подходит к переполнению — по техреференсу «typically half a counter's
maximum value», то есть на `0x80` для байтовых и `0x8000` для словных.
Он не входит в маску `AckIntr` и снимается автоматически после вычитки
насыщенных счётчиков (чтение обнуляет счётчик).

Пороги (`SetRxEarlyThreshold`, `SetTxAvailableThreshold`,
`SetTxStartThreshold`): значение больше 1792 отключает событие,
power-up-дефолт для всех трёх — 2044 (то есть отключено).

Команды (`code = cmd>>11`, `param = cmd&0x7FF`): 0 GlobalReset, 1
SelectWindow, 3/4 RxDisable/Enable, 5 RxReset, 8 RxDiscard, 9/10
TxEnable/Disable, 11 TxReset, 12 FakeIntr, 13 AckIntr (маска `0x69`), 14
SetIntrMask, 15 SetStatusEnb (Read Zero Mask), 16 SetRxFilter (биты:
1=individual, 2=group, 4=broadcast, 8=promiscuous; group также разрешает
broadcast), 17/18/19 RxEarly/TxAvail/TxStart threshold, 21/22
StatsEnable/Disable.

## TX/RX датапас

TX: преамбула — слово длины (бит15 = запросить TX Status) + служебное
слово `0`, затем данные, дополненные до границы DWORD. Кадр короче 60
байт карта дополняет нулями сама. TX-партиция — настоящий FIFO: пока
предыдущий кадр ещё «на проводе», драйвер может писать следующие — они
ставятся в очередь (в пределах TX Free) и уходят по одному, разделённые
стандартным межкадровым интервалом 10 Mbit/s (9.6 мкс). TX Free
учитывает каждую запись целиком (4 байта преамбулы + данные с
DWORD-паддингом) плюс байты кадра, собираемого в данный момент. Запись
сверх TX Free теряется, но счётчик кадра продолжает идти, так что кадр
всё равно доходит до своей длины и завершается ошибкой, а не подвешивает
буфер сборки: взводится sticky TX Overrun в FIFO Diagnostic + Adapter
Failure, передатчик выключается, в стек TX Status кладётся запись с
Underrun (`0x10`). Кадр длиннее 1514 байт завершается как Jabber
(`0x20`). Обе ошибки требуют `TxReset` перед `TxEnable` — до этого
`TxEnable` игнорируется (видно в Net Diagnostic бит 8). FIFO при этом
продолжает принимать байты, как и на реальной карте («the host can
continue to copy the packet to the adapter, since the transmitter is
disabled»). Передача (и, соответственно, TX Status + статистика)
завершается асинхронно, по таймеру `device_network_interface` на
скорости 10 Mbit/s — не в момент последней записи FIFO.

TX Status: успешная передача с запрошенным уведомлением даёт `0xC0`
(Complete + Interrupt Requested — бит уведомления сохраняется в готовой
записи), ошибочная завершается всегда, независимо от бита уведомления.
Стек — 31 запись; когда он заполняется, в читаемом значении появляется
бит Status Overflow (`0x04`) и передатчик выключается; запись в регистр
TX Status (pop) снимает условие и возвращает передатчик в работу — «no
other action is required», как в техреференсе.

Событие TX Available (бит 3 статуса) взводится, когда свободное место
(DWORD-округлённое) превышает порог `SetTxAvailableThreshold` — в том
числе сразу при установке порога, если место уже есть. `AckIntr` по
этому биту снимает его и одновременно возвращает порог в отключённое
состояние (2044), так что его надо переустанавливать каждый раз.

RX: партиция — настоящее байтовое кольцо на 16 КиБ (плюс кольцо
дескрипторов на 256 кадров, которое на ревизии B не является узким
местом: восьмипакетного ограничения 3C509 у неё нет). Принятый кадр
остаётся головой очереди, пока явно не выполнена команда `RX_DISCARD` —
повторное чтение данных пакет не удаляет. Несколько кадров подряд
корректно ставятся в очередь; при нехватке места кадр отбрасывается со
взводом RX overrun (статистика + FIFO Diagnostic бит 11). `RX_DISCARD`
удаляет ровно один пакет и открывает следующий.

RX Bytes в RX Status убывает по мере чтения и уходит в отрицательные
значения (11-битное дополнение до двух) при чтении padding-байтов, как
описано в техреференсе; чтение за пределами padding — RX Underrun +
Adapter Failure. RX Early взводится, пока кадр «на проводе», и гасится
приходом RX Complete: «Whenever RX Complete is set, RX Early will be
clear». Кадр длиннее 1792 байт обрезается по этой границе.

`RxReset` возвращает документированные дефолты: приёмник выключен,
RX-фильтр обнулён, порог RX Early — 2044, FIFO пуст. `TxReset` —
передатчик выключен, TX FIFO и стек TX Status очищены, пороги TX
Available и TX Start возвращены к 2044.

Internal (controller) loopback: `Window 4 +0x06`, любой ненулевой старший
нибл (биты 15:12) включает `set_loopback()` — переданный кадр возвращается
в обычный RX FIFO и подчиняется тем же RX Status/фильтрации/RX_DISCARD
правилам, что и кадр из сети.

## Диагностика

```bash
../mame/mame sprinter -listslots
../mame/mame sprinter -isa1 3c509b -listdevices
../mame/mame sprinter -isa1 3c509b -verbose
```

LOG-каналы в исходнике (`LOG_ID`, `LOG_IO`, `LOG_CMD`, `LOG_NET`,
`LOG_IRQ`) по умолчанию выключены отдельно от `-verbose`, чтобы не
создавать постоянный поток строк; включаются правкой `VERBOSE` в
`3c509b.cpp` при отладке конкретного слоя.

## Проверено

Прямыми Lua-тестами против запущенного `sprinter` (ISA I/O space
`:isa81`, минуя Z80 — тот же путь, что `sprinter_state::isa_r/isa_w`):
полная ID-последовательность и активация, чтение EEPROM через ID-порт с
CIP-задержкой, byte-pair frontend и `Select Window`, полный цикл
TX → internal loopback → RX с DWORD-padding, RX persist-until-discard,
2 и 10 кадров подряд через `RX_DISCARD` (без потерь и с сохранением
порядка), очередь TX из 10 кадров, записанных без ожидания завершения
предыдущего, TX Status peek/pop (глубина > 1, снятие `TX_COMPLETE` на
последнем pop), немедленное срабатывание TX Available при установке
порога до первой передачи, TX/RX Free по факту занятых байт в
SRAM-партициях.

Воспроизводимый набор `tests/3c509b/run.sh` покрывает exact fixture,
dynamic/configured MAC и Window 2, PnP serial/checksums, порчу word `18h`,
два discovery/activation с tag 0, обе ISA-шины и bases `0200h`, `0300h`,
`03E0h`, независимые границы 310 мкс/3000 мс, ранний TX без replay и
save/load во время EEPROM read и link recovery. Отдельный no-backend сценарий
проверяет, что `READY` сам по себе не поднимает Media Status bit 11.

Аппаратные прогоны 8–9 сентября 2026 на 3C509B-TPO assembly
`03-0020-002`, revision 3 подтвердили EEPROM byte order и checksum ranges.
После исправления клиента карта обнаружилась и работала; ID-port Global
Reset давал наблюдаемый link flap и первый успешный кадр через 2–6 секунд,
тогда как повторное подключение к уже работающей карте без reset занимало
0 секунд. Это измерение включает конкретный switch, поэтому MAME использует
воспроизводимые 3000 мс, а не выдаёт диапазон за silicon timing.

Новая аппаратная приёмка всей матрицы после этих изменений MAME остаётся
отдельной задачей: результат headless suite её не заменяет.

## Отличие от rtl8019as

`rtl8019as` — обёртка над готовым MAME-ядром DP8390/RTL8019A
(NE2000-совместимая программная модель). `3c509b` эмулирует другую,
несовместимую по регистрам архитектуру — родной 3Com EtherLink III с
окнами регистров и legacy ID-портом; драйверы для одной карты не подходят
для другой.
